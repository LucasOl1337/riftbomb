Uma distinção que evita outra reescrita

Fonte não é artefato

Podemos escrever o Riftbomb em módulos pequenos e continuar entregando exatamente um HTML. “Usar TypeScript”, “separar arquivos” e “publicar um arquivo” são três decisões independentes.

O erro de categoria

Quando dizemos que o Riftbomb venceu por estar em um HTML, misturamos três eixos diferentes. O HTML atual contém JavaScript; é esse JavaScript que implementa as mecânicas. TypeScript também termina como JavaScript depois da compilação: anotações de tipo são removidas antes do runtime.

1 · Linguagem de autoria

JavaScript, TypeScript ou uma transição gradual entre os dois.

2 · Organização da fonte

Uma unidade grande ou poucos módulos com interfaces reais.

3 · Formato de entrega

Um HTML autocontido ou vários arquivos baixados pelo navegador.

Conclusão: fonte modular não obriga entrega fragmentada. Um bundler percorre imports e dependências e pode produzir uma saída agregada. Embutir também CSS, modelos e áudio em um único HTML exige uma etapa adicional do nosso pipeline, mas não exige fonte monolítica.

Os três projetos que estamos comparando

Riftbomb atual

  • Autoria em JavaScript dentro do HTML.
  • Fonte executável concentrada em um arquivo.
  • Entrega autocontida em um HTML.

Bomb PvP atual

  • Autoria em TypeScript.
  • Dezenas de módulos e ampla superfície interna.
  • Build distribuído em 120 arquivos.

Nossa hipótese: fonte pequena e modular → build → um HTML autocontido

A primeira modularização não será uma reinvenção

O arquivo atual já contém três módulos naturais: Renderer, SfxEngine e Game. Eles possuem nomes de domínio, comportamento substancial e interfaces menores que suas implementações. O primeiro movimento seguro é extrair esses blocos quase intactos, sem redesenhar o jogo durante a movimentação.

index.html                 # shell visual e ponto de entrada
src/main.js                # composição, boot e frame
src/game.js                # classe Game intacta no primeiro passe
src/renderer.js            # classe Renderer + shaders
src/sfx-engine.js          # classe SfxEngine
src/ui-input.js            # DOM, teclado e touch
src/generated/models.js    # payload produzido pelo model-baker
dist/riftbomb.html         # continua sendo o artefato jogável
Provisório significa provisório. Ainda não criaremos engine/, kernel/, systems/, contracts/ ou dezenas de folders de campeão. Primeiro vamos observar mudanças reais e estabilizar uma interface por vez.
Sequência, não indecisão. A direção candidata é TypeScript, mas o primeiro passe mantém .js: extraímos os blocos sem alterar sua semântica, verificamos o jogo e só então tipamos uma fronteira por vez. Assim, se algo quebrar, sabemos se a causa foi movimentação ou tipagem.

Regra que levaremos para a próxima aula

Não criamos um módulo porque um arquivo ficou grande. Criamos um módulo quando uma responsabilidade substancial pode ser escondida atrás de uma interface pequena e possui uma razão real para mudar separadamente.

Isso preserva duas vantagens ao mesmo tempo: localidade para continuar criando vertical slices e seams reais para testar ou substituir o que já estabilizou.
